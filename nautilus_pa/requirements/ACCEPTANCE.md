# ACCEPTANCE — 验收标准

> "完成"的定义。任何任务/需求要进入 ACCEPTED，必须满足本文件；Agent 自述完成不算证据。

## 0. 验收的基本原则

1. **证据优先**：状态变化必须有可复核的证据（命令+输出、Diff、审查结论、哈希）。
2. **测试未执行 ≠ 通过**：跳过的测试按失败处理，必须写明跳过原因。
3. **范围一致**：实际改动的文件必须都在任务 `allowed_paths` 内。
4. **可复现**：任何人按任务里的测试计划重跑，应得到同样结论。
5. **不替人决策**：验收人不能把"我认为可以"写成证据。

## 1. ACCEPTED 十项清单

| # | 检查项 | 证据形式 |
| --- | --- | --- |
| 1 | 需求覆盖：REQ 中每条要求都被实现或明确排除 | 任务验收标准逐条打勾 |
| 2 | 接口符合：对外接口与 `docs/API_CONTRACTS.md` 一致 | 接口差异说明 / 无变更声明 |
| 3 | 范围符合：改动只在 `allowed_paths` 内 | `git diff --stat` |
| 4 | 审查通过：Reviewer 五门禁给出 PASS | `.dsh/reviews/REVIEW-NNN.md` |
| 5 | 测试通过：相关单测/集成/回归全绿 | 测试命令 + 通过数 |
| 6 | 无 P0/P1 缺陷 | 审查结论中的缺陷表 |
| 7 | Diff 已由 Main 审查 | 审查记录 |
| 8 | 测试证据已保存 | 命令输出摘要写入任务 `evidence` |
| 9 | 文档同步：受影响的文档已更新 | `docs/`、`PROJECT_CONTEXT.md` 的改动 |
| 10 | 遗留问题已记录 | 任务 `remaining` 或 `development/CHANGELOG.md` |

## 2. 五道门禁

| 门禁 | 检查内容 | 不通过的表现 |
| --- | --- | --- |
| G1 需求一致性 | 实现是否真的满足 REQ，而非满足任务的字面描述 | 需求点遗漏、口径偏移 |
| G2 架构一致性 | 是否破坏分层、是否依赖反向、是否复制既有逻辑 | `domain/` 导入适配器、逻辑重复 |
| G3 代码质量 | 命名、精确算术、异常路径、无调试残留、最小 diff | 浮点算价格、裸 `/` 切路径、无关重构 |
| G4 自动化测试 | 单测/集成/回归是否覆盖改动，是否被弱化 | 断言被删、测试被跳过、只跑"能过"的 |
| G5 最终验收 | 十项清单逐项核对 | 缺证据、缺文档、缺遗留记录 |

## 3. 缺陷分级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| P0 | 数据丢失、安全、核心不可用、错误交易信号 | 立即阻断，不得验收 |
| P1 | 核心逻辑错误、重大架构偏离 | 必须修复后重审 |
| P2 | 验收前应修的功能/边界问题 | 验收前修复 |
| P3 | 优化、重构、技术债 | 记入待办，可带债验收 |

P0/P1 一律不得带缺陷验收。

## 4. 测试分层要求

| 层 | 位置 | 何时必须跑 |
| --- | --- | --- |
| 单元 | `tests/unit/` | 每次改动 |
| 集成 | `tests/integration/` | 涉及存储/API/引擎链路 |
| 回归（PB） | `regression_cases.yaml` + `application/regression.py` | 涉及结构/状态/决策语义 |
| 规格一致性 | 人工对照规格条款 | 涉及业务语义 |
| 前端 | 浏览器手测 | 涉及 `web/` |

基线命令：

    PYTHONPATH=src python -m pytest -q

改动测试基线数量时，必须在任务 `evidence` 中说明新增/删除了哪些测试及原因。

## 5. 需求级出口条件

阶段出口以 `执行计划.md` 的出口条件为准；阶段出口是下一阶段的准入门槛，不允许"先做后面"。
REQ 只有在全部子任务 ACCEPTED 且出口条件满足时才能标 `DONE`。

## 6. 证据写法

    evidence:
      - command: PYTHONPATH=src python -m pytest tests/unit/test_state.py -q
        result: 42 passed
      - command: git diff --stat
        result: 3 files changed, 118 insertions(+), 9 deletions(-)
      - commit: TASK-002 强制 PATCH 乐观锁 (abc1234)

证据里不要写"已测试通过"这种没有命令的话。
