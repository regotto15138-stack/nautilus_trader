# SPEC-V148-14｜交易成本与合约元数据

> **文档状态：** V1.4.8-COST-R1 修订候选（REVIEW_CANDIDATE）。本章为唯一权威规格第 14 章的修订提案；在跨章节审查及 OPEN_DECISIONS 关闭前不得宣称整体冻结。

## 1. 文档元数据

- 文档 ID：`SPEC-V148-14`（章节 ID，不是 REQ ID）
- 基线版本：V1.4.8 扩充版；修订号：COST-R1
- 范围：ETH-USDT-SWAP.OKX 交易成本、合约元数据、单位风险及回测审计

## 2. 目标与范围

确保入场 sizing、退出风险、净成本和资金流水使用可复现、同币种、同量纲的输入。交易所历史成交与账单优先于估计模型；不推断收益，也不把研究初值当作实盘参数。订单成交机制归第 13 章，止损可执行价格归第 15 章，风险预算与净 R 归第 17 章。

## 3. 规范性要求

### 3.1 成本组成与账本边界

必须覆盖 Maker/Taker 费率、入场/出场滑点、Funding、合约面值或乘数、Tick Size、Lot Size、最小下单量及币种换算。交易成本按 **Fill 级别** 核算，Funding 按 **结算事件级别** 核算，不能把估计成本当成真实账单。交易费用、滑点与 Funding 分别记账，避免重复计入。任何回测净绩效必须说明价格成交模型与成本模型的分界。

### 3.2 合约元数据与量纲（修订）

对每个时间点 `t`，元数据为不可变版本 `InstrumentMetadata(valid_from <= t < valid_to)`，字段至少包括：`instrument_id, instrument_type, contract_value, contract_value_currency, settlement_currency, quote_currency, base_currency, tick_size, lot_size, min_order_qty, max_order_qty, min_notional(if applicable), price_precision, qty_precision, metadata_version, valid_from, valid_to, source, captured_at`。历史版本区间不得重叠；缺口、冲突或交易时点无法解析时拒绝有效回测。更新后的元数据仅对生效时间后的事件生效，不得追改历史成交。跨版本持仓按实际成交时点分别计价，后续风险估值使用估值时点有效的规则，并审计潜在合约条款变更。

**不得假设 OKX 的 `ctVal` 总是以报价币计价。** 必须根据合约类别和 `ctValCcy` 选择定价函数。定义 `V_quote_per_contract(P,t)`：价格 `P` 时每张合约的报价币名义价值；定义 `Q_quote_per_price_unit(t)`：在适用线性报价合约下，价格变化 1 报价币/基础币对应每张合约的报价币 PnL 系数。只有确认合约为线性、面值以基础币计价时，才可取 `Q_quote_per_price_unit = contract_value_base`，并使用下列线性公式。反向或其他结构合约必须提供独立定价/PnL 函数，禁止套用线性乘数。ETH-USDT-SWAP 的具体元数据必须由所用历史数据集验证，不在本规格硬编码。

金额统一先计算为 **结算币**，再以 `FX(currency -> risk_currency, valuation_time, source)` 换算至风险预算币种。FX 缺失/非正/时间不匹配时不准通过风险门禁。计算采用 Decimal 或等价定点精度；中间风险值不隐式 tick 取整；交易所订单价格/数量由第 13、15 章量化。

### 3.3 固定滑点模型（新增）

模型 ID `FIXED_TICKS_V1`，参数 `entry_slippage_ticks >= 0`、`exit_slippage_ticks >= 0`，均为非负整数，默认值 **不擅自指定**，启动时 REQUIRED。`delta_entry = entry_slippage_ticks * tick_size(t_fill)`，`delta_exit = exit_slippage_ticks * tick_size(t_fill)`。模拟执行的参考价格为第 13/15 章给定的无滑点可执行参考价 `P_ref`：

| 交易动作 | 成交价（不利方向） |
|---|---|
| 买入开多 / 买入平空 | `P_fill = P_ref + delta` |
| 卖出开空 / 卖出平多 | `P_fill = P_ref - delta` |

对多头/空头，滑点成本均为 `abs(P_fill-P_ref) * Q_quote_per_price_unit`（线性合约，每张），再转换到风险币种。滑点是成交价偏移：**如果已用偏移后的成交价计算实际 PnL/止损距离，不得再额外扣一次滑点现金流**。模拟报告可将滑点相对基准价的归因金额单列，但归因项不得重复进入总账。实际 Fill 以真实价格为准，不再施加固定滑点。该模型不覆盖冲击成本、订单簿深度、跳空及无法成交风险；触发止损与穿价成交由第 13/15 章优先定义，固定滑点不能把不利跳空“修正”成更优成交。无法取得可靠参考价时拒绝生成有效 Fill。

固定 ticks 模型仅是可复现基线；参数须做 0/1/2/5 ticks 等敏感性实验（不是默认值），并与真实成交分布比较。`slippage_model_version` 必须指向具体算法和参数哈希。

### 3.4 Maker/Taker 与费率适用（新增）

默认模拟策略：**入场使用可成交的市价/可立即成交订单，出场止损使用触发后可成交订单，均按 Taker 估费**；具体支持的订单类型及止损执行机制以第 13/15 章为准。止盈若为主动可成交单按 Taker；若为真实挂单且提供逐笔成交流动性标志则按实际 Maker/Taker。`post_only` 被接受且确认为被动成交，才可按 Maker；仅凭 `LIMIT` 订单类型不能推断 Maker。市价单不能按 Maker。部分成交逐笔分别判断。

优先级：`exchange_fill.liquidity_flag`（可信时）→ 有可验证的撮合/订单簿回放证据 → 无法判定则 **保守按 Taker**；不得因限价单而自动优惠。历史费率按 `account_fee_tier, instrument_id, effective_at, maker_rate, taker_rate, currency, source, fee_schedule_version` 选择，不能假定所有账户适用固定 0.02%/0.05%；负 Maker 费率代表返佣，必须按账单符号记录。模拟费额（每张）为 `fee = notional_settlement(P_fill,t) * applicable_rate`，若交易所费用基数/币种规则不同，必须使用交易所专属 fee calculator；实际费用以逐笔账单为准。手续费与滑点分别核算。

### 3.5 Funding 事件与现金余额（补全）

Funding 不按平均费率或固定 8 小时硬编码。每个历史结算事件至少保存：`event_id, instrument_id, settlement_time_utc, rate, rate_source, funding_interval_start/end, position_qty_at_cutoff, position_side, mark_or_index_price, price_source, nominal_value, funding_currency, signed_amount, bill_id(if actual), metadata_version, data_hash`。实际结算频率、持仓快照截点、计费价格和舍入按该事件对应的交易所历史规则/账单执行；历史规则不可得时禁止宣称有效净收益。

正费率下通常多头支付、空头收取；负费率相反，但必须以该合约当时的交易所符号约定核验。约定 **账户现金流符号**：收入为正、支出为负。若 `rate > 0` 且交易所采用多头付费规则，`signed_funding_long < 0`、`signed_funding_short > 0`；`rate < 0` 方向相反。理论值仅用于与账单核对，不能覆盖实际账单。

事件排序按 `settlement_time_utc` 与确定性事件优先级；结算边界恰好同时成交的持仓归属须依交易所规则及第 03/13 章确定，不得用收盘后持仓反推结算前持仓。结算现金流只记一次：`cash_balance[funding_currency] += signed_amount`；同时记入资金流水及余额快照，保证保证金可用额、权益与清算检查使用更新后的真实余额。Funding 原币金额不可被 FX 换算结果覆盖，换算另建记录。若账单晚到，按事件溯源重建回放，不静默改写已冻结回测结果。

**OD-08 保留：** Funding 如何正式纳入净 PnL、净 R、风险预算及其估值时点，仍为 OPEN_DECISION。在关闭前允许生成原始 Funding 现金流水与余额对账，但不得将其静默忽略或自行并入价格风险/减仓分母，也不得验收相关净绩效。

### 3.6 初始每张合约风险（修订，线性合约）

所有下列项目单位均为 `risk_currency / contract`，`qty` 单位为 `contracts`。设 `s = +1` 多头，`s = -1` 空头；`P_entry_ref` 为无滑点入场参考价，`P_stop_ref` 为按第 15 章确定的退出可执行参考价。`P_entry_worst = P_entry_ref + s*delta_entry`；`P_stop_worst = P_stop_ref - s*delta_exit`。

- `StopLossPriceRisk = max(s*(P_entry_ref-P_stop_ref),0) * Q_quote_per_price_unit`（再做币种换算）。
- `EntrySlippageCost = delta_entry * Q_quote_per_price_unit`。
- `ExitSlippageCost = delta_exit * Q_quote_per_price_unit`。
- `EstimatedEntryFee = FeePerContract(P_entry_worst, entry_liquidity, t_entry)`。
- `EstimatedExitFee = FeePerContract(P_stop_worst, exit_liquidity, t_exit_estimate)`。
- `InitialRiskPerUnit = StopLossPriceRisk + EstimatedEntryFee + EstimatedExitFee + EntrySlippageCost + ExitSlippageCost`。

上述分解在 `P_entry_ref` 至 `P_stop_ref` 为不利方向、且同一线性乘数/FX 估值基础时成立。若止损价位已越过盈亏平衡点、汇率/元数据随时间变化或非线性合约，必须以 `max(EstimatedEntryAllInValue - EstimatedExitAllInValue, 0)` 的方向化全成本损失函数重新计算，不能把各项简化相加造成重复计数或错误。风险估值必须声明 `valuation_time` 和 FX 假设。`InitialRiskPerUnit > 0` 才允许 sizing；零风险或非法值拒绝开仓。

`InitialRiskTotal = qty * InitialRiskPerUnit`；`qty_raw = allowed_initial_risk / InitialRiskPerUnit`，再与最大名义敞口、保证金、交易所最大量约束取最小，并按 Lot Size **向下** 取整。低于最小数量或名义额则拒单；取整后必须再次核验所有限制。预计费用/滑点的保守费率选择不能低估默认 Taker 情景。

### 3.7 当前每张合约风险与引用（修订）

`CurrentRiskPerUnit = CurrentStopLossPriceRisk + EstimatedExitFee + ExitSlippageCost`。线性合约：

- 多头：`CurrentStopLossPriceRisk = max(CurrentExecutablePrice - CurrentStopPrice, 0) * Q_quote_per_price_unit`。
- 空头：`CurrentStopLossPriceRisk = max(CurrentStopPrice - CurrentExecutablePrice, 0) * Q_quote_per_price_unit`。

此处价格风险仅代表**当前参考价格至止损参考价格的潜在额外不利变动**，不等于从实际入场以来的总亏损。`CurrentExecutablePrice` 必须为与方向一致的可执行估值参考价；不能混用中间价与止损成交价。退出费和滑点按当前剩余数量估计；已发生成交费及入场滑点作为沉没成本独立进入 `ActualRisk`/现金账，不在减仓边际分母重复计算。实际已发生风险、仓位级风险、已实现损益、风险预算超限后的减仓顺序及 Funding 预算传导由第 17 章及 OD-08 定义；本章不擅自重写。

### 3.8 版本与审计（修订）

每次回测冻结：`cost_model_version, instrument_metadata_version`（可为时间区间版本集哈希）, `funding_dataset_hash, fee_schedule_version, slippage_model_version`，并记录 `execution_model_version, fx_dataset_hash, parameter_hash, source_data_hash`。每笔 Fill/成本事件记录 `event_id, order_id, fill_id, instrument_id, event_time, available_at, side, qty, ref_price, fill_price, liquidity_flag, fee_rate, fee_amount, fee_currency, slippage_ticks, model_version, metadata_version, fx_rate_id`；字段不适用时显式为 null，不得虚构。

必须校验：版本时间区间无重叠；同一 fill_id/账单 ID 幂等；费率/乘数/币种有效；费用返佣符号；Funding 与余额对账；无重复滑点；回放输出逐笔一致。缺少必需成本、FX 或 Funding 数据时，不得标记有效净收益。

## 5. 验收要求

1. 同一线性合约多头/空头镜像用例：价格差、乘数、每张风险与总风险量纲正确。
2. `FIXED_TICKS_V1`：四种交易动作均为不利方向；零 ticks 无偏移；价格偏移与损益不重复计费。
3. 限价立即成交按 Taker；真实 post-only Maker；部分成交混合 Maker/Taker 分笔核算；缺少标志保守 Taker。
4. 历史费率档位切换、Maker 返佣、费用币种换算及无 FX 失败。
5. Funding 正/负费率、多/空、跨结算边界开平仓、重复账单、晚到账单及现金余额对账。
6. 合约元数据跨版本、时间区间重叠/缺失、tick/lot 变化及非线性合约拒用线性公式。
7. 初始风险预算、Lot Size 向下取整、最小下单量、最大敞口/保证金同时满足。
8. CurrentRiskPerUnit 多空镜像；入场沉没费用不重复进入边际风险；`ActualRisk` 与第 17 章对账。
9. 无成交价/元数据/Funding/费率/换算源时，不得验收净绩效；回放、批量、增量逐笔一致。
10. 对 0/1/2/5 ticks、Maker/Taker 费率变化、Funding 频率变化进行敏感性测试；不将测试参数当作最优值。

验收需保存黄金样本、预期账单、风险计算表、事件日志与模型哈希；冻结条件依第 24 章，数据验收依第 07/21 章。
