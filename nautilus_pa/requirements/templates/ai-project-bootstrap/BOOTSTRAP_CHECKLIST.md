# 新项目 AI 协作启动核对清单

## 范围与权威来源
- [ ] 确认父仓库/子项目边界、平台安全规则、贡献规范与 Git 拓扑。
- [ ] 指定唯一的需求来源、任务状态源、架构/接口源和验收证据位置。
- [ ] 记录权威优先级与变更流程；不要复制出第二套状态台账。
- [ ] 明确项目风险等级、数据敏感性、精度/时间/并发/兼容性要求。

## 项目规则和模板
- [ ] 从 `AGENTS.template.md` 定制项目执行规则并安装为根 AGENTS.md。
- [ ] 建立精简 PROJECT_CONTEXT.md，未知事实标为待验证。
- [ ] 建立 REQUIREMENTS、ACCEPTANCE、CHANGE_REQUESTS 与架构/模块/API文档。
- [ ] 选择 TASK 索引/状态实现，并建立依赖、角色、输入输出、权限、预算、review 模板。
- [ ] 建立 Session handoff 文件与恢复入口。
- [ ] 将路径权限和必要工具权限落实到实际授权/沙箱，而非只写提示词。

## 验证与维护
- [ ] 明确格式检查、最小相关测试、全量测试、构建、集成和部署门禁。
- [ ] 选一个小任务演练 DRAFT→READY→IN_PROGRESS→IMPLEMENTED→REVIEWING→TESTING→ACCEPTED。
- [ ] 验证失败、阻塞、取消和未运行测试不会被报告为成功。
- [ ] 验证用户已有 Git 改动不被覆盖；确认提交需何种人类授权。
- [ ] 每次 Session 启动按项目 AGENTS 检查任务、Git 状态和交接；结束时记录可恢复事实。
