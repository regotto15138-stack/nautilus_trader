## 权威边界与风险限制

- V1.4.8 章节文件 `SPEC-V148-01…25` 是策略语义唯一权威；本目录不覆盖它。
- **五章修订候选**：[03 时间与 Bar](../spec_v1_4_8/03-时间与%20Bar%20处理规范.md)、[04 指标与 ZigZag](../spec_v1_4_8/04-指标与%20ZigZag.md)、[05 Swing 与保护点](../spec_v1_4_8/05-Swing%20结构与保护点.md)、[06 Zone](../spec_v1_4_8/06-Zone%20支撑阻力区域.md)、[14 成本与合约元数据](../spec_v1_4_8/14-交易成本与合约元数据.md) 当前均为 `REVIEW_CANDIDATE`。前后端方案与接口契约只同步其字段、诊断与门禁表达，不构成语义批准；批准与开放决策冻结由 TASK-095 承接，任务台账见 [`tasks.json`](../../.dsh/tasks/tasks.json)。
- 候选期间的验收边界：TASK-029/030/031/032/034/035 及下游只能按 tasks.json 的研究/设计合同推进；`OD-ZZ-01…05`、`OD-ZONE-01…06`、`OD-06`、`OD-08`、结构层 `OPEN_DECISION-*` 必须原样阻断相应输出。
- 已知口径冲突：SPEC-04 将 `occurred_at` 定义为极值来源 Bar 结束时刻，历史 TASK-004 使用 `open_time`；解决前不得按时间键自动对齐或静默重算 Golden。
- SACW 原文提出的技术栈建议（React/TS/FastAPI/PostgreSQL/DuckDB）与当前落地（vanilla JS、标准库 HTTP、SQLite、Parquet）存在差异；以架构迁移决策批准前的当前实现为兼容基线，方案描述目标设计，不得误称已实现。
- P0-E 与 OD-05 尚无确认通过证据；P1-A 暂不准入。OD-01…07 按结构化规格及执行计划保持约束，未决语义不进入接口推断。
- 拆分文件由原规格对应章节正文逐字迁移；不得在拆解时改写策略语义。
